## ٠.٠ ✅ محسوم — قسم الإنتاج ينتمي لفرع تصنيع مستقل، مو retail1

كل الجداول والصفحات المبنية بهالمستند تنتمي لفرع تصنيع جديد **منفصل تماماً**
عن `retail1` (فرع بيع تجريبي، لاحقة `_ret`) يلي كنا نختبر عليه. الفرع الجديد:

|                                                                                                                  |                                                                                                                       |
| ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **الاسم**                                                                                                        | `factory1`                                                                                                            |
| **لاحقة الجداول**                                                                                                | `_fac` (اقتراح متوافق مع نمط `retail1`→`_ret` بمشروعك — قابل للتعديل لو تحدد غيره)                                    |
| **توفير الفرع فعلياً** (صف `branches` + توليد جداوله الأساسية عبر `create_branch_tables.php` + نسخ مجلد الوحدات) | **محادثة تانية مسؤولة عنه — خارج نطاق هالمحادثة**                                                                     |
| **نطاق هالمحادثة**                                                                                               | تجهيز ملفات قسم الإنتاج (والمواد الأولية) جاهزة بلاحقة `_fac` الصحيحة، لتُرفع بمجلد `factory1/` بمجرد ما الفرع يتوفّر |

**مواد أولية بُنيت مسبقاً بهالمحادثة (`raw_materials.php` وملحقاتها):** كود
PHP ما بيحتاج أي تعديل (ديناميكي بالكامل عبر `$_SESSION['table_suffix']`)؛
سكريبت الـSQL تحدَّث ليستخدم `_fac` بدل `_ret`.

**قسم المشتريات (شراء مواد أولية):** ⚠ خارج نطاق هالمحادثة أيضاً — محادثة
المشتريات مالكة `purchases/*.php`. تعليمات التسليم بملف منفصل
(`handoff_to_purchases_conversation.md`).

## ٠. المبادئ الحاكمة (مستنتجة من النقاش + قواعد المشروع العامة)

1. **فصل المخطط عن التنفيذ الفعلي** — "المسار" (Routing) قالب حي يتغيّر مع الوقت،
   لكن أي أمر إنتاج بياخد **لقطة (Snapshot)** منه وقت الإنشاء ويشتغل عليها
   باستقلالية تامة. تعديل القالب لاحقاً **لا يمس** أوامر شغالة.
2. **لا مرجع حي لأي قيمة تاريخية** — تسعيرة العامل/المقاول تُنسخ (snapshot) بلحظة
   التنفيذ الفعلي داخل سجل التنفيذ نفسه، مو تُقرأ حية من جدول العامل وقت
   التقرير — وإلا تغيير سعر مقاول اليوم بيغيّر تكلفة أوامر قديمة مكتملة بالغلط
   (نفس المبدأ المطبّق أصلاً على `exchange_rate` بالفواتير).
3. **أي تعديل مسار على أمر قيد التنفيذ = حدث موثّق، مو تعديل مباشر صامت**
   (`Production Change` بمصطلحك) — سبب + مستخدم + تاريخ + قبل/بعد.
4. **الكمية "الخارجة عن المسار الطبيعي"** — تصميم نهائي (بعد تكرار النقاش):
   - **Good** — تتقدّم عادي
   - **Rework** — ترجع تدور بالمسار (لمرحلة/محطة تُحدَّد وقت التسجيل). علامة
     اختيارية `بدون تكلفة إضافية` (لحالة "المقاول رجّعها مجاناً لأنه غلطه") —
     نفس آلية Rework بالضبط، بس بدون توليد قيد تكلفة جديد لما ترجع.
   - **Scrap** — تخرج نهائياً، قيد خسارة محاسبي فوري
   - **Accept (استخدام كما هو)** — القطعة فيها ملاحظة جودة بسيطة بس بتُحتسب
     Good عادي (تتقدّم بالمسار)، الملاحظة تُحفظ للتقارير بس
   - ⚠ **حُذفت فئة "Reject" المستقلة** — كانت بتحتاج سلسلة مرجعية (تتبّع
     "هاي الكمية شو صار فيها لاحقاً") لتفادي ازدواجية العد؛ استبدلناها
     بـ"سبب عيب + ديسبوزيشن مباشر" بمكان واحد (بند ١ تحت) — أبسط وبنفس القوة
5. **لا حذف لحدث صار فعلياً** — نفس القاعدة الذهبية العامة بالمشروع.
6. **تكلفة العمالة الداخلية ≠ دين حقيقي** — الموظف ماخد راتبه من `payroll.php` بغض النظر عن الإنتاج. أي "تكلفة قطعة" تُحمَّل على WIP من عمل داخلي بتقيد بحساب وسيط (Clearing) مو بحساب دفع فعلي، لتفادي تضخيم المصروف (راتب حقيقي + تكلفة وهمية مكررة).
7. **تكلفة القطعة الكاملة = مواد + عمالة خارجية (دين حقيقي) + عمالة داخلية (محمَّلة/وسيطة) + تكلفة غير مباشرة موزَّعة** — الأربعة كلهم يدخلوا WIP بنفس آلية القيد، بس الطرف الدائن يختلف حسب النوع.

## ٠.١ محطة العمل (Work Center) — توضيح العلاقة

```
المرحلة (خياطة)
   └── محطة عمل داخلية "خط خياطة ١"  → موظفين + تسعيرة معيارية للتكلفة
   └── محطة عمل داخلية "خط خياطة ٢"  → موظفين + تسعيرة معيارية للتكلفة
   └── محطة عمل خارجية "شركة ABC"    → مقاول + تسعيرته الفعلية
```

بدون تخطيط طاقة استيعابية (لا جدولة، لا حدود ساعات/يوم) بهالنسخة — بس تصنيف/تجميع، يسمح لاحقاً بإضافة الجدولة بدون كسر أي شي موجود.

**توضيح مهم:** "الكمية عند المقاول الخارجي بانتظار الرد" **ما بتحتاج جدول
منفصل** — هي فعلياً بس كمية قاعدة بدفتر الكمية الحي (بند ٢) عند محطة عمل
نوعها `خارجية`. إرسال الكمية للمقاول = حركة عادية (نقل مرحلة/محطة لمحطة
المقاول، بدون نتيجة بعد). استلامها منه = التنفيذ يلي بيسجّل النتيجة
(سليم/Rework/Scrap + التكلفة). نفس آلية النقل اليدوي العادية، بدون كيان
جديد.

## ٢. طبقة التشغيل (Transactional — يومي)

| الكيان                                                      | الوصف                                                                                                                                                                                                                                         |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **أمر الإنتاج (Production Order)**                          | موديل + كمية إجمالية + **نسخة المسار المستخدمة وقت الإنشاء** + حالة (تحت)                                                                                                                                                                     |
| **لقطة مسار الأمر (Order Routing Snapshot)**                | نسخة مستقلة تماماً من مراحل القالب، مملوكة للأمر نفسه فقط                                                                                                                                                                                     |
| **تعديل مسار أمر قائم (Change Routing)**                    | حدث موثّق منفصل: أي مرحلة اتضافت/اتشالت/اترتبت، السبب، المستخدم، التاريخ — **ممنوع** لو الأمر `مكتمل`/`ملغى`                                                                                                                                  |
| **دفتر الكمية الحي لكل مرحلة**                              | "شو قاعد هلق بكل مرحلة" — بيسمح بالتقسيم الجزئي (جزء بمرحلة ٣، جزء بمرحلة ١)                                                                                                                                                                  |
| **سجل تنفيذ المراحل (Stage Execution)**                     | كل تنفيذ فعلي: من مرحلة/محطة عمل لمرحلة/محطة عمل، **كمية داخلة + كمية Good + كمية Rework**، مين نفّذ، تسعيرته **المنسوخة وقتها**، التكلفة المحسوبة                                                                                            |
| **نتائج الجودة (Quality Results / أسباب العيوب)** ✅ محدَّث | جدول حقيقي (مو enum)، مربوط بكل تنفيذ: سبب العيب (تمزق، مقاس خاطئ...) + كمية + شدة + **ديسبوزيشن مباشر واحد**: `Rework` (بتكلفة أو بعلامة `بدون تكلفة إضافية`) / `Scrap` / `Accept`. لا حالة "بانتظار قرار" وسيطة — القرار يُتخذ لحظة التسجيل |
| **المواد الفعلية المستهلكة بالتنفيذ**                       | ما استُهلك **فعلياً** بهاي المرحلة (يختلف عن "المخطَّط" بالقالب) — بيولّد حركة `raw_material_movements` (`production_out`) **+ قيد محاسبي مرافق: مدين WIP / دائن مخزون المواد الأولية** ✅ فجوة كانت ناقصة، انضافت                            |
| **قيد الخسارة (Scrap)**                                     | تلقائي لحظة تسجيل ديسبوزيشن Scrap: مدين "خسارة إنتاج"، دائن "منتج تحت التصنيع" — بقيمة نصيبها من التكلفة المتراكمة لحد هاي المرحلة                                                                                                            |
| **قيد WIP لكل تنفيذ مقاول خارجي**                           | مدين "منتج تحت التصنيع" (أصل)، دائن حساب المقاول المخصص (دين حقيقي)                                                                                                                                                                           |
| **قيد WIP لكل تنفيذ داخلي (موظف)** ✅ جديد                  | مدين "منتج تحت التصنيع"، دائن **"عمالة داخلية مُحمَّلة"** (حساب وسيط Clearing — مو دين حقيقي، الموظف ماخد راتبه من الرواتب أصلاً). المطابقة بين هالحساب ومصروف الرواتب الفعلي = مرحلة لاحقة منفصلة، غير مبنية الآن.                           |
| **قيد التكلفة غير المباشرة المخصَّصة (Overhead)** ✅ جديد   | لكل تنفيذ: مدين WIP / دائن حساب مجمّع التكلفة، بقيمة محسوبة حسب طريقة توزيعه (تسعيرة ثابتة أو % من العمالة المباشرة لهاي المرحلة)                                                                                                             |
| **إغلاق الأمر (Completion)**                                | لما الكمية الصافية (الإجمالي - كل الـScrap المتراكم) توصل آخر مرحلة بالكامل: مدين "مخزون منتج جاهز"، دائن "منتج تحت التصنيع" بكامل التكلفة، + زيادة فعلية برصيد المنتج                                                                        |
| **مصير الإغلاق/الإلغاء (Order Disposition)** ✅ جديد        | سجل قرارات إغلاق أمر متوقف: إرجاع مواد / نقل WIP لأمر تاني / Scrap / خسارة إنتاج مستقلة — تفصيل كامل ببند ٥.١                                                                                                                                 |

## ٣. آلة حالات أمر الإنتاج

```
مسودة (Draft) ──► مُعتمَد (Released) ──► تحت التنفيذ (In Production) ──► مكتمل (Completed)
     │                    │                        │
     └────────────────────┴────────────────────────┴──► ملغى (Cancelled)
                                                          عبر معالج "إغلاق/إلغاء" (بند ٥.١) — ليس زر مباشر
```

| الحالة          | تعديل المسار                                                                            | تسجيل تنفيذ جديد                                        |
| --------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| **مسودة**       | حر ومباشر (لسا ما بدأ فعلياً، ما في حدث "Change" موثّق لأنه ما في شي يتغيّر عليه أصلاً) | ممنوع                                                   |
| **مُعتمَد**     | يُفضَّل التثبيت (تحذير لا منع صارم — نقطة مفتوحة ٥.٤)                                   | ممنوع لحد أول تنفيذ (عندها تلقائياً تصير `تحت التنفيذ`) |
| **تحت التنفيذ** | **ممنوع مباشرة** — فقط عبر `Change Routing` موثّق                                       | مسموح، هو صلب الصفحة اليومية                            |
| **مكتمل**       | ممنوع نهائياً                                                                           | ممنوع نهائياً                                           |
| **ملغى**        | ممنوع                                                                                   | ممنوع                                                   |

## ٥. نقاط لسا مفتوحة (لازم نحسمها قبل البناء)

### ٥.١ ✅ محسوم — إغلاق/إلغاء أمر الإنتاج (Cancel ≠ Scrap تلقائي)

**قرار نهائي:** "الإلغاء" مو زر بسيط ولا مرادف لـ"خسارة تلقائية". هو **إجراء
معالج (wizard)** مستقل اسمه "إغلاق/إلغاء أمر الإنتاج" — لما يُفعَّل، النظام
يفحص أول شي الوضع الفعلي للأمر:

- في تكاليف مسجَّلة فعلياً؟ (تسعيرة موردي الخدمةاتقيّدت بحسابهم)
- في مواد مصروفة فعلياً؟
- في كمية WIP عالقة (بأي مرحلة)؟
- في كمية سليمة (Good) خلصت فعلاً؟
- في كمية Scrap مسجَّلة مسبقاً؟

وبعدين **يطلب من المستخدم يحدد مصير كل رصيد متبقي**، مو يقرر تلقائياً:

| الخيار                                  | الأثر                                                                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **إرجاع مواد**                          | مواد اتصرفت بالتنفيذ بس فعلياً رجعت سليمة → حركة عكسية بجدول حركات المواد الأولية (رصيدها يرجع)                                                        |
| **نقل WIP لأمر تاني**                   | الكمية العالقة (وتكلفتها المتراكمة) تنتقل لأمر إنتاج قائم تاني، مو تضيع                                                                                |
| **تسجيل Scrap**                         | خسارة فعلية حقيقية → نفس قيد الـScrap العادي (بند ٢)                                                                                                   |
| **إثبات خسارة إنتاج (Production Loss)** | تكلفة اتصرفت فعلياً (مثلاً فصالة اتدفعلها) بس ما في قطعة مادية مقابلها تتسجل كـScrap — قيد خسارة مستقل، مختلف عن Scrap لأنه مو مرتبط بكمية مادية محددة |

**القاعدة الذهبية المطبَّقة هون تحديداً:** الإلغاء يوقف الأمر عن قبول تسجيلات
جديدة، **بس ما بيمحي ولا يعدّل أي قيد قديم** — كل قرار من الأربعة فوق
بيولّد **قيد/حركة جديدة مستقلة**، مو تعديل على شي موجود. المبلغ المستحق
لأي مقاول اشتغل فعلاً **يضل مستحق** بغض النظر عن مصير الأمر — الإلغاء ما
بيلغي دين حقيقي.

**كيان جديد لازم ينضاف للطبقة التشغيلية:** `production_order_dispositions`
(أو تسمية مشابهة) — سجل كل قرار مصير اتخذ وقت الإغلاق: النوع (إرجاع
مواد/نقل WIP/Scrap/خسارة)، الكمية، الوجهة (لو نقل WIP، أي أمر استلمها)،
السبب، مين نفّذ، تاريخه، ومرجع القيد المحاسبي المرتبط.

### ٥.٢ ✅ محسوم — صلاحية Scrap منفصلة

تسجيل Scrap (خسارة فعلية بقيد محاسبي) يحتاج **صلاحية اعتماد مستقلة**
(زي `can_confirm` المستخدمة بتأكيد الفواتير)، منفصلة عن صلاحية تسجيل
التنفيذ العادي (`production.board:execute` مثلاً مقابل
`production.board:confirm_scrap`). نفس المنطق ينطبق على "إثبات خسارة
إنتاج" بمعالج الإغلاق (بند ٥.١) — كلاهما قيد خسارة حقيقي.

### ٥.٣ ✅ محسوم — Reject حُذفت، استُبدلت بـ"سبب عيب + ديسبوزيشن مباشر"

راجع بند ٠.٤ و١ فوق — Rework (بعلامة اختيارية "بدون تكلفة إضافية" لحالة
المقاول اللي يرجّعها مجاناً) / Scrap / Accept، بديسبوزيشن واحد مباشر
لحظة الاكتشاف، بدون سلسلة مرجعية معقّدة ولا حالة "بانتظار قرار" وسيطة.

### ٥.٥ ✅ محسوم — لا BOM مستقل

مواد كل مرحلة + تكلفتها المعيارية تعيش جوا تعريف مرحلة المسار نفسها،
وتُنسخ مع لقطة المسار وقت إنشاء الأمر. كافي لتغطية الهدف (ثبات تاريخي)
بدون بنية إضافية.

### ٥.٦ الفرق العملي بين `مُعتمَد` (Released) و`مسودة` (Draft)

هل `مُعتمَد` مجرد قفل للمسار بس، أو فيها خطوة موافقة/فحص إضافية قبل
البدء الفعلي (متل "استلام أمر الشغل" بمرحلة القص)؟
