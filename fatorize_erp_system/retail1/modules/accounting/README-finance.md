# README-finance.md — قسم المالية والمحاسبة (فرع retail1)

> مرجع تقني للحالة **النهائية الحالية** لقسم المالية والمحاسبة فقط —
> مش سجل تحديثات. لأي بند مؤجَّل/مخطَّط للمستقبل، راجع
> `تحديثات_مستقبلية.md` بجذر المشروع. هذا الملف يوصف "شو الوضع الآن"،
> مش "شو تغيّر ومتى".

---

## ١. نظرة عامة

قسم المالية تحت `retail1/modules/accounting/` — عشر صفحات رئيسية مرتبطة
بشريط تبويبات موحَّد، بالإضافة لصفحتين سياقيتين (كشف حساب) تُفتحان من
أقسام تانية (المبيعات/المشتريات).

**المبدأ الأساسي لكل القسم**: كل عملية مالية = قيد محاسبي متوازن
(مدين = دائن)، مسجَّل بعملة الفرع الأساسية دايماً، مع الاحتفاظ بالمبلغ
الأصلي بعملته الحقيقية للعرض والتدقيق.

## ٣. شجرة الحسابات (`account_charts_{TS}`)

### الأعمدة الأساسية
| العمود | الوصف |
|---|---|
| `code`, `name`, `parent_id`, `account_type` | بنية الشجرة القياسية (asset/liability/equity/revenue/expense) |
| `currency_id` | عملة الحساب نفسه (FK لجدول `currencies`) |
| `balance` | الرصيد **بعملة الحساب نفسه** |
| `base_balance` | الرصيد **بعملة الفرع الأساسية** — دايماً محدَّث بالتوازي مع `balance` |
| `cash_flow_category` | تصنيف صريح مخزَّن (`operating`/`investing`/`financing`/`excluded`/`none`) — يغذّي تقرير التدفقات النقدية، قابل للتعديل من مودال إضافة/تعديل الحساب |

### قاعدة التحديث (مطبَّقة بكل نقطة ترحيل قيد بالنظام)
كل عملية ترحيل/إلغاء قيد بتحدّث العمودين سوا بنفس الاستعلام:
```sql
UPDATE account_charts SET
    base_balance = base_balance + [صافي المبلغ بعملة الفرع],
    balance = balance + (CASE WHEN currency_id = [عملة السطر] THEN original_amount ELSE net END)
WHERE id = [الحساب]
```
`balance` بيتحدّث بـ`original_amount` الحقيقي المخزَّن بسطر القيد نفسه —
**مش** بإعادة اشتقاقه من سعر صرف "اليوم" (لأنه سعر الصرف بيتغيّر، وإعادة
الحساب بسعر مختلف عن سعر وقت المعاملة بينتج رقم غلط).

### حسابات مخصصة تلقائياً لكل كيان
عميل جديد، مورد جديد، شركة شحن جديدة → حساب ذمة فرعي يتولّد تلقائياً
تحت الحساب الأب المضبوط بـ`account_settings.php` (مثال: `2.1.1.003`
"ذمم شركة الوسيم للألبسة" تحت `2.1.1` "ذمم الموردين"). **لا حساب مشترك
لكل الكيانات** — رصيد كل كيان بمفرده قابل للقراءة مباشرة من الشجرة.

### حماية الحذف
حساب برصيد غير صفري (بأي من العملتين) **لا يمكن حذفه** — الزر يظهر
معطَّلاً بتلميح يوضّح السبب.

## ٤. نظام العملات

### الجداول
| الجدول | النطاق | الوصف |
|---|---|---|
| `currencies` | عالمي (بدون suffix) | العملة، الرمز، **سعر الصرف** (موحَّد لكل الفروع — حقيقة سوق واحدة) |
| `currency_branch_links` | عالمي | **مصدر الحقيقة الوحيد** لأي عملية تخص عملة+فرع: أي عملة مربوطة بأي فرع، وبأي حساب صندوق/بنك تحديداً بشجرة ذاك الفرع |
| `invoice_account_settings_{TS}` | خاص بكل فرع | مفاتيح ديناميكية (`cash_{code}`, `bank_{code}`) لكل عملة — **يظل المصدر المعتمد فعلياً بكل صفحات المالية** (treasury/receipts/payments/taxes) عند البحث عن حساب صندوق/بنك لعملة معيّنة |

> ⚠️ **عمودان قديمان بجدول `currencies`** (`cash_account_id`,
> `bank_account_id`) لسا موجودان لفترة انتقالية — رابط عرض تاريخي بس،
> **مش مصدر معتمد**. سيُحذفان لاحقاً بعد التأكد الكامل من اعتماد كل
> الكود على `currency_branch_links`.

### مبدأ الفصل الجوهري
- **هوية العملة وسعرها** → مركزية عالمياً (لا يصح اختلاف سعر نفس العملة بين فرعين بنفس اللحظة)
- **حساب الصندوق/البنك المرتبط بها** → خاص بكل فرع لحاله (نفس العملة، حسابات فيزيائية مختلفة تماماً لكل فرع)

### دورة حياة الربط (عملة ↔ فرع)
1. **عملة جديدة كلياً** (`currencies.php` → إضافة): تُنشأ + تُربط تلقائياً بفرع المُنشئ بخطوة واحدة (صف بـ`currency_branch_links` + حسابا صندوق/بنك بشجرة حسابات فرعه + سطرا `invoice_account_settings`)
2. **تفعيل عملة موجودة بفرع تاني**: زر "ربط" بجدول العملات (يظهر بس للعملات غير المربوطة بفرع المستخدم الحالي، صف الجدول يتلوّن تحذيرياً) → مودال معاينة بأكواد حسابات مقترحة (قابلة للتعديل) → تأكيد → نفس عملية الربط، بصلاحيات المستخدم العادية بفرعه (لا تصعيد صلاحيات عبر فروع)
3. **إلغاء ربط/حذف عملة**: يتحقق أول من رصيد صفري بحسابات ذاك الفرع تحديداً، وإلا يُرفض

### التحويل/التصريف بين عملتين مختلفتين (`treasury.php`)
مبلغين منفصلين (خارج من المصدر بعملته، داخل للوجهة بعملته) — أي فرق
بينهم ينسجّل صراحة كربح أو خسارة صرف حقيقية على حسابين منفصلين
(`fx_gain` إيراد، `fx_loss` مصروف)، لا "netting" ولا تحويل بمبلغ واحد
وهمي.

## ٥. القيود المحاسبية (`journal_entries_{TS}` / `journal_entry_items_{TS}`)

- **العملة دايماً `currency_id`** (FK رقمي) — لا عمود `currency` نصي بأي مكان
- قيد يدوي واحد = عملة واحدة موحَّدة لكل أسطره (اختيار من `currencies` + سعر صرف لحظة الإدخال)
- `debit`/`credit` بكل سطر = **بعملة الفرع الأساسية دايماً** (`base_amount`)؛ `original_amount` = المبلغ الحقيقي بعملة السطر الأصلية (للعرض والتدقيق، ولتحديث `balance` الصحيح على شجرة الحسابات)
- الترحيل والإلغاء عامّان بالتصميم — بيلوبان على كل أسطر القيد بغض النظر عن العدد (٢ أسطر أو ٥)، فأي قيد بأسطر إضافية (استقطاع ضريبي، فرق صرف...) بيترحّل/يُلغى صح بدون كود خاص

## ٦. سندات القبض والدفع

- حساب ذمة مخصص تلقائياً لكل عميل/مورد (راجع §٣)
- توزيع اختياري على فواتير مستحقة (بيع للقبض، شراء للدفع)
- **سندات الدفع**: دعم "دفعة عامة" بدون مورد محدَّد (حساب مباشر)، ودعم **استقطاع ضريبي فعلي** — قيد ٣ أسطر: مدين ذمة المورد بالكامل (كأنه استلم المبلغ الإجمالي)، دائن الصندوق بالصافي بعد الاستقطاع، دائن "ضريبة استقطاع مستحقة" بالفرق
- حساب الصندوق/البنك يُحدَّد تلقائياً حسب عملة السند (`cash_{code}` من الإعدادات)، مع تحقق سيرفر إضافي إنه عملة الحساب المختار يدوياً (لو اختير) تطابق عملة السند

## ٧. الضرائب والرسوم (`taxes.php`)

### أنواع الضرائب (`tax_types_{TS}`)
ثلاث نطاقات: `sales` (مبيعات)، `purchase` (مشتريات)، `withholding`
(استقطاع) — نسبة مئوية أو مبلغ ثابت، مربوطة اختيارياً بحساب محاسبي.

**الحالة الفعلية للربط**: نطاق `withholding` **مربوط فعلياً** بسندات
الدفع للموردين. نطاقا `sales`/`purchase` **بنية جاهزة غير مربوطة بعد**
بفواتير البيع/الشراء (مخطَّط للنسخة القادمة، بقرار: ضريبة واحدة على
مستوى الفاتورة كاملة، لا لكل بند لحاله).

### الرسوم الثابتة/الدورية (`fixed_fees_{TS}`)
رسوم مو مرتبطة بفاتورة (رخص، اشتراكات) — مرة واحدة/شهري/سنوي، بتسديد
يُنشئ قيد تلقائي (مدين مصروف الرسم، دائن الصندوق) ويولّد الاستحقاق
التالي تلقائياً للرسوم الدورية.

## ٨. التقارير المالية (`reports.php`)

| التقرير | الطبيعة | ملاحظة منهجية |
|---|---|---|
| **الميزانية العمومية** | لحظة زمنية (تاريخ مختار، افتراضياً اليوم) | لو تاريخ ماضي، تُعاد بناء الأرصدة من حركة القيود المرحّلة لغاية ذاك التاريخ (مش من `base_balance` الحالي). فيها **سطر اصطناعي "أرباح الفترة الحالية (غير مقفلة)"** يعوّض غياب قيد إقفال فترة فعلي — بدونه الأصول ما تساوي الالتزامات + حقوق الملكية |
| **الأرباح والخسائر** | حركة فترة (من-إلى) | **حركة الفترة بس**، مش رصيد تراكمي — مُتحقَّق فعلياً ببيانات حقيقية (شراء+بيع طابق الحساب اليدوي تماماً) |
| **التدفقات النقدية** | حركة فترة، طريقة مباشرة | تصنيف تلقائي (تشغيلي/استثماري/تمويلي) حسب `cash_flow_category` للحساب "المهيمن" الآخر بنفس القيد الذي يحوي سطر صندوق/بنك |

## ٩. كشف حساب عميل/مورد

صفحتان سياقيتان مستقلتان (`customer_statement.php` / `supplier_statement.php`)،
تُفتحان دايماً بمعرِّف صريح من صفحة إدارة العملاء/الموردين. تسحب حركة
الحساب المخصص للكيان مباشرة من `journal_entry_items` (نفس منطق "حركة
الحساب" بـ`accounts.php`)، بفلترة إما بفترة تاريخ أو بـ"آخر N عملية"،
مع رصيد تراكمي وزر طباعة.

## ١٠. الصلاحيات

كل صفحة رئيسية إلها مفتاح صلاحية مستقل بجدول `modules` (`finance.accounts`,
`finance.journal`, `finance.receipts`, `finance.payments`, `finance.treasury`,
`finance.taxes`, `finance.reports`, `finance.currencies`,
`finance.shipping_carriers`, `finance.account_settings`) — كلهن تحت
`parent_key = 'finance'`. صفحتا كشف الحساب تستخدمان صلاحية
`finance.reports` (لا مفتاح منفصل لهما).
