# قسم الموارد البشرية والرواتب — فرع retail1

مرجع الحالة النهائية الحالية لقسم HR بالكامل: الصفحات، قاعدة البيانات، والآلية المحاسبية. هاد المستند يوثّق **الوضع الحالي فقط**، مش تاريخ التعديلات.

---

## ١. الصفحات

جميعها تحت `retail1/modules/hr/`، بواجهة موحَّدة (breadcrumb عبر `renderBreadcrumb()`، شريط تبويبات يربط الأربعة ببعض).

| الملف | الوظيفة | مفتاح الصلاحية |
|---|---|---|
| `employees.php` | إدارة بيانات الموظفين، جدول الدوام الأسبوعي الشخصي، إنشاء الحسابات الفرعية المحاسبية تلقائياً | `hr.employees` |
| `attendance.php` | تسجيل الحضور اليومي/الجماعي، إدارة العطل الرسمية (مودال داخلي، لا صفحة مستقلة) | `hr.attendance` (والعطل: `hr.holidays`) |
| `payroll.php` | احتساب/اعتماد/صرف الرواتب، السلف، المكافآت | `hr.payroll` (الاعتماد/الإلغاء يحتاجون درجة `confirm`) |
| `reports.php` | كشف حساب موظف (شامل راتب/سلف/مكافآت/حضور/رصيد GL حي) | `hr.reports` |

**ملف API منفصل:** `retail1/api/payroll_api.php` — كل عمليات الحساب والترحيل المحاسبي لصفحة `payroll.php` تمر من هون (لا يوجد أي `INSERT`/`UPDATE` مباشر بـ`payroll.php` نفسها لجداول الرواتب/القيود).

**ملاحظة توجيه:** أي صفحة جديدة بالقسم لازم تُضاف يدوياً لخريطة `moduleUrl()` بـ`includes/sidebar.php`، وإلا رابط الشريط الجانبي بيرجع لصفحة فهرسة الملفات (`#`).

## ٢. تفاصيل الاستخدام لكل صفحة

### ٢.١ الموظفون (`employees.php`)

**نموذج إضافة/تعديل موظف:**
- بيانات أساسية: الاسم الكامل، المسمى الوظيفي، القسم (قائمة ثابتة بالكود حالياً — راجع "نقاط مفتوحة")، الهاتف، الإيميل، تاريخ التعيين، الحالة (نشط/غير نشط).
- الراتب: نوع الراتب (شهري/أسبوعي/يومي/ساعي)، الراتب الأساسي، العملة (قائمة من جدول `currencies`، مرتَّبة `is_base DESC` — أول عملة بالقائمة = عملة الفرع الأساسية افتراضياً)، معامل الإضافي (`overtime_multiplier`، افتراضي ١.٥).
- **جدول الدوام الأسبوعي الشخصي:** لكل يوم من أيام الأسبوع، حقلا "من" و"إلى" (بصيغة ٢٤ ساعة، أرقام صحيحة). ترك الحقلين فاضيين لأي يوم = هذا اليوم عطلته الأسبوعية. هالجدول هو الأساس يلي تُبنى عليه: حساب أجر الساعة الأسبوعي، توليد فترات الأسابيع المتواصلة، وقفل الحضور.
- حساب بنكي، ملاحظات.

**عند الحفظ (إضافة فقط):** ينشئ تلقائياً الحسابين الفرعيين المحاسبيين (مستحقات + سلف) — راجع قسم ٤. لو فشل (الحسابات الأب غير مضبوطة)، العملية كاملة تترجع (لا يُنشأ الموظف بدون حساباته).

**القائمة:** فلترة حسب القسم والحالة (client-side)، عرض عملة كل موظف ورمزها، تبديل الحالة (نشط/موقوف) بضغطة مباشرة. شريط تنبيه أحمر تلقائي أعلى الصفحة لو في موظفين قدامى بدون حسابات فرعية، مع زر "رحّل الحسابات الآن".

### ٢.٢ الحضور والانصراف (`attendance.php`)

**العرض اليومي:** اختيار تاريخ (افتراضياً اليوم، زر "اليوم" للرجوع السريع) → قائمة كل الموظفين النشطين يلي هذا اليوم مو عطلتهم الأسبوعية الشخصية. لكل موظف: وقت الحضور/الانصراف الفعلي، ساعات العمل المحسوبة تلقائياً (`check_out - check_in`)، ساعات إضافية، وحالة (`present`/`absent`/`late`/`half_day`/`holiday`).

**الحفظ:**
- **فردي (`save_attendance`):** تعديل صف موظف واحد، أي وقت.
- **حفظ سريع (`quick_save`):** ضغطة وحدة تسجّل الموظف "حاضر" بأوقات دوامه المجدولة الافتراضية، بدون فتح نموذج.
- **دوام جماعي (`bulk_attendance`):** زر "دوام جماعي" — يطبّق نفس وقت الحضور/الانصراف على كل الموظفين (أو مجموعة مختارة) بضغطة وحدة ليوم معيّن. الموظفين يلي فترتهم مقفلة (`accrued`/`paid`) يتم تخطيهم تلقائياً مع عداد منفصل ("مقفل برواتب معتمدة: X")، الباقي ينحفظ عادي.

**القفل المحاسبي:** أي حفظ (فردي أو جماعي) على تاريخ واقع بفترة `hr_payroll` بحالة `accrued`/`paid` لنفس الموظف يُرفض، إلا لصاحب صلاحية `hr.payroll:confirm`.

**العطل الرسمية:** زر "العطل الرسمية" (يظهر بصلاحية `hr.holidays`) بيفتح **مودال داخل نفس الصفحة** (مو صفحة مستقلة) — قائمة `public_holidays`: تاريخ، اسم، وخيار "متكرر سنوياً" (`is_recurring`). إضافة/حذف مباشر من نفس المودال. هالبيانات مرجعية على مستوى الفرع كامل (مش لكل موظف لحاله)، وتدخل مباشرة بحساب صافي راتب أي موظف تشمله الفترة — راجع "حساب العطل الرسمية" بقسم ٤.

### ٢.٣ السلف والمكافآت (داخل `payroll.php`)

**مودال سلفة جديدة:** اختيار الموظف، المبلغ، العملة (افتراضياً عملة الفرع الأساسية)، عدد الأقساط (القسط الشهري يُحسب ويُعرض تلقائياً = المبلغ ÷ عدد الأقساط)، صندوق الصرف (**إجباري** — القائمة تُفلتر تلقائياً لتُبرز الصناديق المطابقة لعملة السلفة)، السبب. لو عملة السلفة ≠ عملة الفرع الأساسية، يظهر حقل سعر صرف (عرضي فقط، بزر "جلب السعر" من جدول العملات). لا حد لعدد السلف النشطة لنفس الموظف.

**إلغاء سلفة:** مسموح فقط لو ما انخصم منها ولا قسط بعد (`paid_installments=0`) — قيد إلغاء منفصل (راجع قسم ٤)، لا حذف.

**مودال مكافأة جديدة:** الموظف، التاريخ، النوع (أداء/عيد/عمولة/نقل/سكن/أخرى)، المبلغ، العملة، وصف اختياري. بدون أي قيد محاسبي فوري — تنضم لمصروف الراتب تلقائياً وقت اعتماد أقرب فترة راتب تشملها.

**إلغاء مكافأة:** إلغاء ناعم (الحالة تصير "ملغاة")، لا حذف فعلي من الجدول — حتى لو كانت أصلاً دخلت براتب مُعتمَد سابقاً (راجع نقطة مفتوحة بقسم ٧).

## ٣. قاعدة البيانات

كل الجداول بلاحقة `_{TS}` (مثلاً `_ret`)، تُنشأ تلقائياً (`CREATE TABLE IF NOT EXISTS`) عند أول استخدام لكل فرع.

### `hr_employees`
البيانات الشخصية والوظيفية + جدول الدوام الأسبوعي (`{يوم}_from`/`{يوم}_to`، فاضي = عطلته الأسبوعية) + `salary_type` (`monthly`/`weekly`/`daily`/`hourly`) + `basic_salary` + `currency_id`.

**أعمدة محاسبية:**
- `payable_account_id` — معرّف الحساب الفرعي "مستحقات هذا الموظف" بشجرة الحسابات (liability).
- `loan_account_id` — معرّف الحساب الفرعي "سلف هذا الموظف" (asset).

كلاهما يُنشأ تلقائياً عند إضافة موظف جديد (راجع قسم ٤).

### `hr_attendance`
`employee_id`, `attendance_date`, `check_in`, `check_out`, `hours_worked`, `overtime_hours`, `attendance_status` (`present`/`absent`/`late`/`half_day`/`holiday`), `notes`.

**قفل محاسبي:** أي `INSERT`/`UPDATE` (فردي أو جماعي) بيتحقق أولاً: هل هذا التاريخ ضمن فترة `hr_payroll` بحالة `accrued`/`paid` لنفس الموظف؟ لو إي، يُرفض إلا لصاحب صلاحية `hr.payroll:confirm`.

### `public_holidays`
`holiday_date`, `name` — يُدار بالكامل من مودال داخل `attendance.php` (لا صفحة/رابط مستقل).

### `hr_payroll`
سجل كل فترة راتب لكل موظف: `employee_id`, `payroll_month`, `week_number`, `period_from`, `period_to`, `basic_salary`, `working_days`, `working_hours`, `overtime_hours`, `overtime_amount`, `bonus_total`, `loan_deduction`, `net_salary`, `currency_id`, `payment_status`.

`payment_status`: `pending` → `accrued` → `paid` (أو رجوع لـ`pending` عبر إلغاء الاعتماد، أو لـ`accrued` عبر إلغاء الصرف).

**أعمدة القيود:** `accrual_entry_id`, `payment_entry_id`, `cancel_accrual_entry_id`, `cancel_payment_entry_id` — أربعة قيود محتملة لكل سجل، كل وحدة موثَّقة لحالها (لا تعديل/حذف لأي قيد سابق أبداً).

### `hr_loans`
`employee_id`, `loan_date`, `amount`, `currency_id`, `installments`, `paid_installments`, `paid_amount` (تراكمي، المصدر الحقيقي للمتبقي — `amount - paid_amount`)، `monthly_deduction`, `status` (`active`/`completed`/`cancelled`), `journal_entry_id`, `cancel_entry_id`.

**لا يوجد حد أقصى** لعدد السلف النشطة لنفس الموظف بنفس الوقت.

### `hr_bonuses`
`employee_id`, `bonus_date`, `bonus_type`, `amount`, `currency_id`, `description`, `status` (`active`/`cancelled` — لا يوجد `DELETE` فعلي).

### `hr_payroll_loan_allocations`
جدول تتبّع دقيق: `payroll_id`, `loan_id`, `amount`, `reversed`. يسجّل بالضبط أي سلفة أخذت قديش من كل عملية اعتماد — أساس عملية "إلغاء الاعتماد" الدقيقة.

## ٤. حساب الراتب (`calculate` بـ`payroll_api.php`)

المدخلات: الموظف + `period_from`/`period_to` (نطاق الفترة، محدَّد مسبقاً من `get_emp_periods`).

### أجر الساعة (`hrRate`) — حسب نوع الراتب

| النوع | الصيغة |
|---|---|
| `hourly` | `basic_salary` مباشرة (بدون أي قسمة) |
| `daily` | `basic_salary ÷ 8` (مكافئ نظري للإضافي فقط؛ الأجر الأساسي = `basic_salary × أيام الحضور`) |
| `weekly` | `basic_salary ÷ مجموع ساعات الدوام المجدولة أسبوعياً` |
| `monthly` | `basic_salary ÷ مجموع ساعات الدوام المجدولة فعلياً بالشهر التقويمي المحدَّد` (يُحسب ديناميكياً يوم-يوم، مطروحاً منه أيام عطلة الموظف الأسبوعية الحقيقية بذاك الشهر بالذات — **ليس رقماً ثابتاً كـ"٢٢×٨"**) |

### الأجر المكتسب (موحَّد لكل الأنواع ما عدا `daily`)
```
earned = hrRate × الساعات الفعلية المسجَّلة بالحضور (hours_worked)
```
لـ`daily`: `earned = basic_salary × عدد أيام الحضور الفعلية`.

### توليد فترات الأسبوع (لموظف `salary_type=weekly`)
**أسابيع متواصلة حقيقية**، مرتكزة على يوم عطلة الموظف الأسبوعية الشخصي (أول يوم `{يوم}_from` فاضي بملفه) — الأسبوع يبلش أول يوم دوام بعد عطلته مباشرة، بغض النظر عن حدود الشهر التقويمي. لو أسبوع امتد بين شهرين، بينحسب كامل بشهر واحد (الشهر يلي بلش فيه الأسبوع)، لا يتقطّع عند نهاية الشهر.

### حساب العطل الرسمية (`holiday_amount` + `holiday_ot_amt`)
كل يوم عطلة رسمية (`public_holidays`) بالفترة يعطي الموظف **استحقاقين منفصلين محتملين**:

1. **الاستحقاق الأساسي (`holiday_amount`)** — `عدد أيام العطلة × hrRate × 8`، يُحسب **دايماً** لكل يوم عطلة بالفترة بغض النظر اشتغل الموظف فيه ولا لأ (حقه الأساسي بيوم إجازة مدفوعة).
2. **إضافي العطلة (`holiday_ot_amt`)** — لو الموظف اشتغل فعلياً بيوم العطلة (حضور مسجَّل بساعات > ٠ لذاك التاريخ)، تلك الساعات (أو اليوم كامل لـ`daily`) **تُطرح من الحساب العادي** (`totalHours`/`workDays`، منعاً للازدواج) وتُحسب لحالها بمعامل `overtime_multiplier` **الخاص بهذا الموظف تحديداً** (من `hr_employees`، مو رقم ثابت ١.٥ أو ٢):
   ```
   holiday_ot_amt = (ساعات/أيام العطلة المشتغلة) × hrRate × overtime_multiplier
   ```
   يعني الموظف يلي اشتغل بعطلة رسمية بياخد **التعويضين سوا** (الاستحقاق الأساسي + الإضافي)، لا واحد بدل التاني.

### الإجمالي
```
gross = earned + overtime_amount + holiday_amount + holiday_ot_amt + bonus_total
net   = gross − loan_deduction
```
`loan_deduction` الافتراضي = مجموع `monthly_deduction` لكل السلف النشطة، **قابل للتعديل يدوياً** بمودال الاحتساب (مبلغ حر جزئي أو كامل، بحد أقصى = إجمالي المتبقي الفعلي `SUM(amount-paid_amount)`، متحقَّق منه بالسيرفر مو بس الواجهة).

## ٥. الآلية المحاسبية (Accrual — استحقاق منفصل عن الدفع)

### مبدأ الحسابات الفرعية
كل موظف (عند الإنشاء فقط) ياخد **حسابين فرعيين تلقائياً** بشجرة الحسابات، تحت الحسابين الأب المضبوطين بصفحة إعدادات الربط المحاسبي (`salary_payable` و`employee_advance`) — نفس نمط العملاء/الموردين بالضبط:
- `مستحقات {اسم الموظف}` — liability، كود `{parent}.00N`.
- `سلف {اسم الموظف}` — asset، كود `{parent}.00N`.

لو الحسابان الأب غير مضبوطين، إنشاء موظف جديد يُرفض برسالة صريحة. **موظفون قدامى** (قبل تفعيل هالميزة) بدون هالحسابين يظهرون بشريط تنبيه أحمر بأعلى `employees.php`، مع زر "رحّل الحسابات الآن" (`backfill_accounts`).

### دورة حياة الفترة الواحدة

```
pending → [اعتماد] → accrued → [صرف] → paid
            ↑                     ↓
        [إلغاء اعتماد]      [إلغاء صرف]
```

كل انتقال = فعل صريح من المستخدم (زر). **لا يوجد أي أتمتة بتاريخ تقويمي** — القرار المحاسبي مرتبط بلحظة اعتماد/صرف المسير الفعلية، لا بيوم ثابت بالشهر.

### ١) الاعتماد (`accrue`)
```
مدين: مصروف الرواتب (gross = earned + overtime + holiday_amount + holiday_ot_amt + bonus)
    دائن: سلف الموظف [حسابه الفرعي]        (loan_deduction، توزَّع FIFO لو أكتر من سلفة نشطة)
    دائن: مستحقات الموظف [حسابه الفرعي]     (net)
```
كل توزيع على سلفة يتسجّل بـ`hr_payroll_loan_allocations` (دقة كاملة للإلغاء لاحقاً). قسط السلفة (`paid_amount`) ينخصم **هون**، مو وقت الصرف الفعلي.

### ٢) الصرف (`pay`)
لو الفترة `accrued` أصلاً:
```
مدين: مستحقات الموظف [حسابه الفرعي]     (المبلغ نفسه بالضبط من قيد الاستحقاق — لا إعادة حساب)
    دائن: الصندوق/البنك
```
لو الفترة لسا `pending` (موظف تخطّى خطوة الاعتماد — توافقية قديمة): مسار مباشر بديل `مدين مصروف رواتب / دائن صندوق`، بخطوة وحدة.

### ٣) إلغاء الاعتماد (`cancel_accrual`) — يتطلب `hr.payroll:confirm`
قيد عكسي منفصل يعكس كل سطر بقيد الاستحقاق الأصلي بالضبط (القيد الأصلي لا يُلمس)، + عكس دقيق لكل سلفة تأثرت (من `hr_payroll_loan_allocations`، لا إعادة حساب). الفترة ترجع `pending`.

### ٤) إلغاء الصرف (`cancel_payment`) — نفس الصلاحية
قيد عكسي لقيد التصفية فقط. الفترة ترجع `accrued`.

### السلف
```
add_loan   → مدين سلف الموظف [حسابه الفرعي] / دائن الصندوق   (فوري وقت الصرف)
delete_loan → مسموح فقط لو paid_installments=0 → مستند إلغاء بقيد عكسي منفصل (نفس فلسفة مرتجع المشتريات، لا حذف/تعديل للقيد الأصلي)
```

### المكافآت
`add_bonus` بدون قيد فوري — بتنضم لـ`gross` وقت الاعتماد. `delete_bonus` = إلغاء ناعم (`status='cancelled'`)، لا `DELETE` فعلي.

## ٦. العملة

**مصدر الحقيقة الوحيد لكل حساب فعلي:** جدول `currencies` (دالة مركزية `payrollSafeRate()`). لا وجود لأي استدعاء API خارجي — زر "جلب السعر" بالواجهة (`get_currency_rate`) بيقرأ من نفس الجدول، **للعرض فقط**؛ الباك-إند لا يثق بأي رقم قادم من الواجهة لحساب `base_amount` الفعلي تحت أي ظرف.

عملة الفرع الأساسية تُجلب عبر `JOIN currencies ON code = branches.base_currency` (العمود النصي المضمون دايماً)، لا `branches.base_currency_id` (موجود لكنه nullable وغير مضمون التعبئة).

## ٨. نقاط مفتوحة موثَّقة (خارج النطاق الحالي، غير مبنية)

- **توليد الأسابيع المتواصلة** (قسم ٤) بيفترض **يوم عطلة أسبوعية واحد** بالضبط لكل موظف. موظف بعطلتين متتاليتين (مثلاً جمعة+سبت) بياخد أول يوم فاضي بس كنقطة ارتكاز — يشتغل صح غالباً، بس ما انفحص صراحة لهالحالة.
- `delete_bonus` لا يتحقق من كون المكافأة دخلت أصلاً براتب `accrued`/`paid` قبل السماح بالإلغاء.
- قائمة الأقسام بـ`employees.php` (`$deptLabels`) لسا مصفوفة PHP ثابتة، مش جدول حقيقي.
- جداول HR الخمسة (`hr_attendance`, `public_holidays`, `hr_payroll`, `hr_loans`, `hr_bonuses`) بدون `FOREIGN KEY` حقيقية.
- إجازة مدفوعة بالحضور (`leave='paid'`) بتنسجل كـ`present` بدون ملاحظة تميّزها.
- نظام إشعارات استباقي لدورة الرواتب (تنبيه عند نهاية فترة) — مؤجَّل لجلسة مستقلة شاملة كل المشروع (`notifications_{TS}` schema-only حالياً).
- تقريرا "ملخص حضور وغياب" و"تكلفة الرواتب حسب القسم" بصفحة `reports.php` — مخطَّطين، غير مبنيين بعد (بس كشف حساب الموظف شغّال).
- `suppliers.php` فيه نفس نمط باگ العملة الثابتة (`?: 1`) — غير مُصلح، خارج نطاق قسم HR.
